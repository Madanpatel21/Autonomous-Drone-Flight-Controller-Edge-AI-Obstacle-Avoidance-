## Protocol versions (must agree, and are checked on every run)

| Item | Value | Where |
|---|---|---|
| Telemetry status schema | **2** (payload 53 B, `action` at offset 45) | `telemetry.h` / `gs_protocol.py` |
| Command gate frame version | **1** (frame: MAGIC 'C', VER, TYPE, LEN, payload, CRC16-CCITT) | `cmd_gate.h` |
| ICD-02 companion frame | v1 (`0xA5 0x5A`, CRC16 over header+payload, resync) | `icd02_frame.h` |
| Parameter blob version | **1** (`[params][crc16]`) | `parameters.c` |

`12_manufacturing/tools/audit_release_manifest.py` re-reads these from both sides
and fails if the flight controller and the ground station disagree — a decoder
behind its encoder is how a fleet loses telemetry silently.

## Honest status

* `COM-004`, `GS-002`, `GS-003` are **PARTIAL**: the command *gate* on the FC is
  written and tested against 10/10 hostile frames, but **no live command
  transport exists** — its only input today is a simulation probe log
  (`FC_SIM_CMD_LOG`). A gate with no wire behind it protects against a threat that
  has not been connected yet.
* The GS is a dependency-free Python 3 CLI, tested on real firmware-generated byte
  logs, not on hand-built fixtures.
